3. Measure complete command subprocess wall time, including startup, data reads, computation, and rendering. Use unprofiled measurements with one warm-up and five timed samples per case. 4. Profile measured slow cases to rank actual hotspots before changing code. Separate import/startup, I/O/validation, computation, rendering, and external work. Profiling directs investigation; unprofiled subprocess measurements determine gains. Reuse existing helpers and dependencies; avoid a general benchmark framework or speculative refactor.
5. For one evidence-backed hypothesis per round, first add a failing reproducer/regression test and observe the expected failure, then implement the smallest correct change. Check exact full-report JSON parity against the preserved authoritative implementation on frozen inputs. Any cache/read shortcut must preserve invalidation and recover safely from missing, stale, corrupt, or incompatible disposable state. 7. Apply the stopping rule after each correct, comparable round: gain is the largest nonnegative per-case median reduction relative to the previously retained implementation.
